# 一起制作空间壁纸

欢迎贡献代码、作品、文档和可复现的问题报告。先选择你要完成的事情：

| 你想做什么 | 从这里开始 |
| --- | --- |
| 分享新作品或新修订 | [市场投稿指南](../guides/壁纸市场创作者入门.md) |
| 制作一个原生作品 | [SDK 入门](../../Packages/com.spatialwallpaper.sdk/Documentation~/GettingStarted.md) |
| 修改客户端、SDK 或工具 | [开发指南](DEVELOPMENT.md) |

| 交流作品体验 | 从作品详情打开关联 Issue；[原创示例](https://github.com/KyaKayKya/Spatial-Wallpaper-Community/issues/3) |

## 提交代码或文档

1. 从仓库唯一活动 dev 分支创建自己的任务分支；名称以 GitHub 实际分支为准。
2. 只修改相关文件。说明修改前后的行为，列出实际执行的检查和未执行项。
3. 创建 PR 指向该活动 dev 分支。界面改动附真实截图；不要把概念图称为已实现界面。
4. 等维护者审查；修复后保留历史。项目使用 merge commit，不要求你强推或重写公共历史。

公开仓库接受社区 PR。维护者将采纳的通用修改先带回私有开发源、验证并合入开发分支，再从冻结提交同步公开源码；不要用反复覆盖公共目录的方式丢掉社区贡献。市场登记、评论关联及撤回状态由公开仓库的独立 PR 维护，不由开发源码同步覆盖。

## 投稿作品

每个作品保留稳定 GUID，每个新修订提供新的版本与不可变 Release 资产。提交一个包含实际 packageSha256 的元数据文件；只注册仓库不代表未来版本自动获批。二进制放 GitHub Release，不把缓存或全部 Unity 资产塞进 Git 历史。

在投稿前核实所有资源许可。署名、付费购买凭证或验证器通过，不自动等于可以再分发。审核要求、组织账号证明、下架和撤回见[市场维护指南](../guides/壁纸市场维护.md)。

## 提供有用的问题报告

附系统版本、SDK/包修订、复现步骤、预期与实际结果、错误文本。作品问题加 GUID 和包 SHA256；声音问题说明静音、每目标音量与系统设备。分享最小必要日志，不上传摄像头原始画面、私有存档、凭据或他人的素材。

对安全问题，先检查仓库是否提供私密漏洞报告入口；没有时只公开最少必要的影响说明，避免附可直接利用的凭据或用户数据。不要将“脚本隔离”当作所有资源或 GPU 风险都已消除。

## 许可

你应当有权提交相应内容，并说明第三方来源。项目自有代码使用 [MIT](../../LICENSE)；独立作品、第三方代码与素材仍按各自许可分发。提交不改变这些边界。

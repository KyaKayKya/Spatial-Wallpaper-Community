# 场景固定窗口规范

这是用户确认的所有场景共同约束。新建、迁移或调整场景时，先建立下面的空间关系，再做美术、灯光和重复排列。白色展示柜是参考；不能把开放世界普通相机画面直接当作窗口场景交付。

## 固定的正面

在显示屏坐标系中，X 向右、Y 向上、Z 向场景内部。显示平面是 Z=0，眼位在 Z<0。制作时使用宽 W、高 H、深 D 的参考长方体，范围为 `[-W/2,W/2] × [-H/2,H/2] × [0,D]`。默认 W=0.53 米、H=0.298125 米，与展示柜相同，比例为 16:9。D 可按场景单独调整。参考盒用于定位，不能当成开放场景的裁剪边界。

作者默认框与运行时有效窗口分开。适配后的有效窗口四角必须投影到视口的 (0,0)、(1,0)、(1,1)、(0,1)，且不随合法眼位改变；裁剪或扩展后，原作者框四角不要求仍在屏幕四角。不得拉伸模型或用黑边代替全画面覆盖。

默认保上下：窄屏裁左右、宽屏扩展左右；用户可选保左右：宽屏裁上下、窄屏扩展上下。偏好按本机作品和显示目标分别保存。作者可用扩展场景、同面墙等保证覆盖；SDK 检查推荐观察范围，但不夹紧有效眼位。

工程默认采用居中适配：作者框 Wa×Ha，当前有效视口 Wv×Hv；保上下取统一尺度 s=Hv/Ha，保左右取 s=Wv/Wa。有效窗口在作者坐标的范围为 Wv/s×Hv/s；这不是只缩放 X/Y，内容深度与前景出屏距离也用同一尺度。居中是工程默认，不增加首轮锚点编辑器。实际物理／名义尺度和五参数 viewport 转换需联调验证，不能改变设备参数以补构图。

地板位于作者框 Y=-H/2，从 Z=0 开始；默认保上下时真实网格前缘覆盖有效窗口下方两个角。选择保左右后允许地板交线因上下裁剪或扩展不再贴屏幕下沿，不能抬地板补偿；作者负责补足新增可见区域。先以参考盒建立正确的空间关系，再按场景需要向横向和纵深重复模型、灯阵和地面标线，形成持续延伸的空间。Parking 的电视堆只保留一组。最终移除或隐藏辅助盒，不显示实体侧壁、顶盖或参考盒侧边造成的地面截断。只有内容本身就是柜体、房间等封闭空间时，才保留内容自身的墙壁。

使用 `WindowProjection` 的离轴投影；屏幕坐标架保持刚性且单位缩放。内容可以在独立的模型根节点中随实际显示尺寸等比缩放，不能随眼位移动。禁止用相机旋转、移动屏幕平面或抬地板来补视觉贴边。开放场景的地面可以扩展以覆盖合法眼位范围，但仍须与固定盒底共面。

## 编辑辅助和运行内容

### 制作基准与运行时可选调平

用户在 2026-10-18 真人试用后明确取消独立台面调平，替代此前将内景旋转作为冗余功能的方案。制作与运行沿用共面基准；观看高低由参考眼位调整，不旋转内景、相机或屏幕。旧 demo 的非零旋转配置需要显式迁移到共面基准；不能保留旧旋转后声称满足本规范。

白色展柜校准 demo 将后退层板和摆件放入 `InteriorContent_A`，固定柜壳保留制作位置；校准水果与正式摆件使用同一个根和参数。开放场景若需要共同地面调平，须另外验证覆盖，不能仅复用展柜的允许范围。

`DisplaySceneVolume` 保存盒子的尺寸，只提供按需线框辅助，没有 Renderer、Collider、追踪输入或全局渲染状态。选中模型根节点并启用 `showGuide` 才显示编辑线框；交付时关闭。不要为验收盒添加可见实体壳、前玻璃或遮挡内容的边框。隐藏辅助盒后仍保留尺寸与验证契约。

Parking 的 `Assets/Parking/Settings/ParkingBox.asset` 设置 authored metres 深度，范围 39–360。修改后执行 `Spatial Wallpaper/Parking/Rebuild scene and player`，同步重建地板、灯阵和裁剪深度。参考盒局部宽 12、高 6.75，通过 0.53/12 的等比缩放对应显示屏。参考盒的宽度不限制灯阵总宽度，灯阵使用原模型的横向与纵深间距扩展。深度修改后必须重新验证并录制，旧视频不再代表当前布局。

## 必须保留的验证

1. 检查适配后的有效窗口世界坐标与实际显示区域四角一致，同时记录作者原框的裁剪／扩展；不只检查投影公式自己构造的点。
2. 默认保上下时检查真实地面覆盖两个有效窗口下角、与作者盒底共面；保左右时检查实际裁剪／扩展及画面覆盖，不强制地面贴下沿。开放场景的地面和阵列覆盖各眼位可见区域。不得再次把“全部实例位于参考盒内”作为开放场景通过条件。
3. 在 16:9、16:10、4:3、超宽和竖屏以及两种适配方式下，用左右、上下、近远眼位验证有效窗口角点；记录像素误差。旧固定比例用例的 0.01 像素是原测试目标，不直接当作尚未验证的新适配门槛。
4. 核对参考盒不渲染、电视未重复、移除内容不影响相机及眼位输入。改变显示尺寸后也必须保持等比关系。
5. 查看真实 Player 画面，确认边缘接地、材质、阴影及重复排列。几何测试通过不代表美术效果已通过。

Parking 使用 `tools/parking/run.py runtime` 检查几何和生命周期，`stills`、`video`、`hold` 生成实际画面，`tools/parking/verify_capture.py` 检查录制证据。任何场景的实现若没有相应验证，应明确标记未验证，不能省略约束。

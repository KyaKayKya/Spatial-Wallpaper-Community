# 发布与维护原生壁纸市场

本指南供市场维护者核查投稿、生成签名可安装索引、处理反馈和撤回。公开仓库为 [Spatial-Wallpaper-Community](https://github.com/KyaKayKya/Spatial-Wallpaper-Community)。源码提供真实发布命令；只有 GitHub Release 中存在经核对的产物才算上线。不要把离线夹具、PR 检查或候选 Ed25519 索引标为正式服务。

## 配置一次发布环境

在公开市场仓库部署审核后的工具、schemas、投稿模板与工作流。私有开发仓库保留历史；公开源码快照不携带私有 Git 历史、开发缓存或未获分发权的资产。活动分支使用 dev/vX.Y，main 等待用户验收。

需要管理员一次完成以下部署操作：

1. 在公开仓库保留 Issues，并为每件作品创建一条真实评论 Issue；无须启用 Discussions。维护者管理标签、隐藏/锁定、举报和移除内容。不要给未创建的帖子编造 URL。
2. 将可信 Windows 验证器发行到标签 native-sdk-0.4.0-preview.1 的 NativeValidator-Windows.zip。ZIP 根目录只能有 NativeValidator.exe、NativeValidator.exe.config、Newtonsoft.Json.dll、native-platform-library.json、build.json 五个文件；build.json.files 记录其余四个文件的 SHA256。源提交和平台库必须与发行身份匹配。
3. 创建 market-publish environment，限制允许的活动 dev 分支并设置独立维护者审核。配置 secret MARKET_SIGNING_PEM 为至少 3072 位 RSA 私钥 PEM；配置变量 MARKET_KEY_ID 和 MARKET_VALIDATOR_SHA256（整个 ZIP 的 SHA256）。私钥不进入 Git、日志、PR 或公开附件。
4. 在产品 Resources/Library/MarketTrust.json 固定公开仓库、两个索引 URL、keyId、modulus 和 exponent。公钥只能通过受信任产品更新变更，不能从下载索引自报的字段更新。
5. 若从私有开发仓库跨仓发布，配置仅限公开市场仓库 contents:write 的细粒度 secret MARKET_DEPLOY_TOKEN。直接在公开仓库运行时使用其自身 GITHUB_TOKEN。PR 检查不接触任何发布 secret。
6. 在上述检查完成后将 MARKET_PUBLICATION_ENABLED 设为 true，运行受保护发布工作流并核对实际 Release。未完成的配置属于待部署事项，不能记录为线上通过。

客户端固定地址为：

- [published.json](https://github.com/KyaKayKya/Spatial-Wallpaper-Community/releases/download/market-index/published.json)
- [published.sig.json](https://github.com/KyaKayKya/Spatial-Wallpaper-Community/releases/download/market-index/published.sig.json)

tools.market.publish 默认使用该仓库；受信任部署可通过 MARKET_REPOSITORY 更改仓库，但必须同步产品信任配置和评论绑定。不要从投稿 JSON 读取此参数。

## 检查投稿

market-check.yml 使用 pull_request_target，只授予 contents:read 和 pull-requests:read。它检出事件中的 base.sha，执行已审核的工具和依赖，然后通过 GitHub API 读取精确 head 的一份新增元数据。它不检出 PR head、不运行作者代码、不执行作者安装脚本，没有签名 secret 或写权限。Action 固定完整 SHA，checkout 不持久化凭据。

初次登记使用 registration schema；修订使用 submission schema。只允许一个新增的精确路径。清单来自作者默认分支的确切提交，核对数字仓库/所有者、listingConsent、稳定 GUID、修订、正式 Release、单个 .spatial 资产、实际下载大小和摘要。组织/协作者控制证明由维护者另行核查。不要因 PR 自报安全通过而跳过准入。

准备可信验证器后，可以在维护者终端运行同一检查：

~~~powershell
python -m pip install --requirement market/requirements.txt
python -m tools.market.publish prepare-validator --sha256 VALIDATOR_ZIP_SHA256 --output Validation/Market/validator
python -m tools.market.publish check-pr --number PR_NUMBER --head PR_HEAD_SHA --validator-config Validation/Market/validator/validator-config.json --output Validation/Market/submission-check.json
~~~

替换三个大写占位值。公开读取可匿名，令牌仅发送到 GitHub API；Release 包和预览使用无凭据请求。HTTP、限流、未知重定向、超时和缺失分页直接报错，不写出空成功结果。检查中的 NativeValidator 只解析元数据和字节码，不渲染投稿内容，不运行作者程序集。

## 审核后生成并签名

market-publish.yml 在活动 dev 的审核合并后、人工 dispatch 或每日观察时运行，使用单一并发组和受保护 environment。它重新从 API 收集作者默认分支与 Release，不消费 PR 工件中的通过标记。权限只有发布所需 contents:write，签名 secret 只提供给最终发布步骤。

本地维护命令如下；不加 --upload 只生成可审阅文件：

~~~powershell
python -m tools.market.publish build --validator-config Validation/Market/validator/validator-config.json --private-key PRIVATE_KEY_PEM --key-id KEY_ID --source-sha SOURCE_COMMIT --output Validation/Market/published
~~~

PRIVATE_KEY_PEM 是受保护的本地 PEM，KEY_ID 对应产品固定公钥，SOURCE_COMMIT 是公开工具/内容源的确切提交。发布环境添加 --upload。工具验证 NativeValidator、配置、Newtonsoft.Json 及可信平台索引的完整依赖摘要；执行前再次检查，不能让投稿者选择 EXE、平台索引或本地路径。

每个资产由发布器再次下载，实际 SHA256 必须与已收集的数字 Release/asset 身份一致。可信报告必须匹配实际字节、schema5、SDK 0.4.0-preview.1、ABI1、作品 GUID、修订、实际能力标签和 verified 许可记录，且 license_share:true。发布前重新核对仓库所有者和资产 ID，防止检查后删除/重传。最终 admission.policy 为 native-admission-v1，绑定 build.identity 和实际 packageAssetId；报告保留验证器的 native-schema5-platform-index-v1 细分策略。

发布输出包括 published.json、published.sig.json、validation-reports.json 和 stats.json。索引 schemaVersion 为 2、kind 为 published；状态只允许 published/revoked。签名覆盖 published.json 的原始 UTF-8 字节，含工具输出的末尾换行。算法为 RSA-PKCS1-SHA256，签名前缀为 ASCII spatial-market-published-v2 加一个零字节；envelope 只含 algorithm、keyId、sha256、signature。解析后重新序列化不保持签名；不得修改换行、空白或编码。

先在 draft 中完整上传 market-published-N 审计产物，完成后发布该代。已发布代不可换字节，同代不同摘要拒绝；失败的未发布 draft 可以重试。随后替换固定 market-index 的两个附件，均不设为产品 latest。更新两个附件期间可能短暂不匹配：客户端拒绝新数据并保留上次验证缓存。发布器从最高完整、签名正确的审计代继续，因此下一次发布能修复稳定附件的部分更新。

客户端验证固定公钥、原始摘要、签名、代数、防回放、身份、下载限制和本地资源准入。过期缓存可浏览但不能继续发起安装；本地已安装/正在播放的确切修订不受索引过期影响。索引签名不替代资源准入、脚本隔离、渲染故障处理或 GPU 风险控制。

## 配置作品评论和详情

维护者在审核源码中的 market/details.json 配置真实帖子。键为 数字作者仓库ID:作品GUID；作品修订保留原帖。发布器自动读取该文件，也可显式传 --details。示例中的数字需替换为实际帖子：

~~~json
{
  "123456789:11111111-2222-4333-8444-555555555555": {
    "comments": {
      "kind": "issues",
      "url": "https://github.com/KyaKayKya/Spatial-Wallpaper-Community/issues/12",
      "number": 12
    }
  }
}
~~~

创建帖子时在正文保存完整一行标记：

~~~text
<!-- spatial-market:123456789:11111111-2222-4333-8444-555555555555 -->
~~~

只配置维护者确认的帖子；链接必须精确指向所选市场仓库的 issues/number。客户端通过系统浏览器让用户匿名查看、GitHub 登录后回复，不要求 PAT，也不抓网页冒充 API。删除/隐藏/锁定帖子沿用 GitHub 治理；保留映射并说明原因，不偷偷换到别的作品。description/preview 默认来自作者清单，维护者可在 details 中审阅覆盖；未提供的字段省略，不能输出 null 占位。

## 统计七日热度

每日从 GitHub Release 资产 API 的 download_count 获取观察，按数字 asset ID 和确切 build 绑定。榜单使用最近七个自然日的下载增量；只有完整窗口且无跨窗口未分配增量时才输出 downloads7d，否则为 null。首次采样的历史累计值不伪装成七日数据。删除资产、漏测、限流或计数下降不记成真实零或新增用户；下降保持高水位并记录异常。

排序由客户端按非空七日下载量降序、稳定键打破并列；未知热度保留明确提示。旧时间窗口自然退出，避免永久累计值垄断。下载次数包括重复下载、更新和机器人，不等于安装人数、评分或点赞，也不能彻底防刷。客户端缓存有过期时间；网络错误保留上次已验证数据并显示错误，不生成虚假排名。

## 下架、举报与恢复

在 market/revocations.json 的 works 中写稳定 key，或 builds 中写确切 build.identity，经审核后重新发布。已登记来源移除时保留 revoked 墓碑和先前准入身份，不要求重新下载已删除的包。下架阻止继续发现/安装，不静默卸载、删除存档、切换正在播放的修订或重置用户音量。恢复必须去除撤销记录、重新核对真实 Release 与许可，再显式发布。

侵权、恶意内容、隐私和行为异常在[市场 Issues](https://github.com/KyaKayKya/Spatial-Wallpaper-Community/issues)举报，附稳定 key、build.identity 和包 SHA256。维护者保留审计依据，说明拒绝/隐藏/锁定/撤回原因。报告中的本地路径、存档或个人信息不要直接公开。

## 验证边界

运行市场针对性测试：

~~~powershell
python -m unittest discover -s tests/market
~~~

测试涵盖真实字节与报告绑定、拒绝错误 schema/SDK/世代/许可、原始签名字节篡改、防回放、撤回墓碑、预览预算及工作流权限。测试夹具使用惰性字节和显式注入的可信报告，不能当作真实作品已发布证据。真实 NativeValidator、签名公钥、五件作品、客户端安装链路和 GitHub 部署要用冻结发行物另核对。旧 python -m tools.market dry-run 仍保留 SDK 无关候选重放，输出不可安装；不能用它替代本指南的 published 工具。

# 创作并投稿原生壁纸

本指南供原生 SDK 作者导出、发布和提交一件可审核的作品。公开市场仓库为 [Spatial-Wallpaper-Community](https://github.com/KyaKayKya/Spatial-Wallpaper-Community)。安装和播放使用发行包，不需要 Python、Unity、GitHub 登录或个人访问令牌。创作工具依赖与播放器运行依赖分开提供。

## 导出并检查原生包

准备匹配发行版的 SDK、NativeValidator.exe、可信 native-platform-library.json 和创作示例。SDK 身份为 0.4.0-preview.1、schema5、scene-command ABI1；这是预览版本。Unity 创作依赖和实际导出入口见[原生导出工具说明](../../tools/wallpapers/README-native.md)。异步脚本示例为 Packages/com.spatialwallpaper.sdk/Samples~/NativeScripts/AsyncViewStorage.cs。

从真正的原生导出得到 manifest.json 和 script.json 后，在 SDK 工具目录运行：

~~~powershell
python ./tools/wallpapers/package_native.py --manifest ./manifest.json --script ./script.json --validator ./NativeValidator.exe --platform-index ./native-platform-library.json --output ./my-wallpaper.spatial
./NativeValidator.exe --package ./my-wallpaper.spatial --platform-index ./native-platform-library.json
~~~

检查退出码为 0，并核对输出的 valid、schema、sdk、command_abi、sha256、work_id、revision、capabilities、license_share 和 license_records。work_id 使用规范的小写 GUID，例如 11111111-2222-4333-8444-555555555555；以后每次修订保留该值。revision 是作者修订，不能复用一个修订号替换字节。不要把旧 schema4 包改版本号当作原生导出。

市场只接受 license_share:true，且每条资源记录的 redistribution 为 verified。填写脚本、模型、材质、贴图、Shader、音乐和音效的来源、许可与署名，保留授权证明。仓库可写权限不证明原创或分发权。随产品提供的原作品本地验证包保留 local-validation 标记；没有许可时不要公开上传它们或改成 share。

可信平台库验证器只接纳其明确支持的场景与资源绑定。外来 Scene、Prefab、任意 DLL、插件和 Editor 代码不能借投稿加载进宿主；需要对应资源准入实现和可信发行支持。验证成功也不证明画面、声音、脚本行为、驱动或 GPU 风险已经验收。

## 发布作者 Release

在自己的公开 GitHub 仓库保存创作源码和根文件 wallpaper.json。将大型 .spatial 产物放入 GitHub Release 资产，不提交开发缓存、Library 或整份资产历史。每件作品每个修订只能指定一个完整 .spatial 包，不能拆卷；市场单包下载预算为 64 MiB，原生验证器另执行自己的结构和资源预算。

先取得数字身份：

~~~powershell
gh api repos/AUTHOR/WALLPAPER --jq .id
gh api users/AUTHOR --jq .id
~~~

将 AUTHOR/WALLPAPER 替换为作者仓库，AUTHOR 替换为 GitHub 用户名。按实际验证器输出填写 wallpaper.json，下面的 GUID、数字身份、版本和许可证仅演示字段格式：

~~~json
{
  "schemaVersion": 1,
  "repositoryId": 123456789,
  "listingConsent": true,
  "works": [{
    "id": "11111111-2222-4333-8444-555555555555",
    "title": "My wallpaper",
    "version": "1.0.0",
    "releaseTag": "v1.0.0",
    "sdk": "0.4.0-preview.1",
    "capabilities": ["view-data"],
    "assets": ["my-wallpaper.spatial"],
    "description": "作品操作、声音层次与适用显示目标。",
    "attribution": [{
      "name": "Author",
      "githubUserId": 123456,
      "license": "CC0-1.0"
    }]
  }]
}
~~~

id 必须与包的 work_id 完全相同，version 必须与 revision 相同。capabilities 必须等于可信验证器从字节码实际推导的能力集合；attribution 应覆盖包内全部许可，不要使用与资源无关的示例许可证。

可选 preview 为 PNG，最多 2 MiB、2048×2048 像素。使用含完整 40 位提交 SHA 的 raw.githubusercontent.com 地址；也接受受限的 GitHub 用户图片/附件地址，发布器拒绝未知重定向。预览下载失败或超预算会阻止本次发布，不用占位图冒充真实作品。

提交 wallpaper.json 到作者仓库默认分支，再发布确切的正式 Release：

~~~powershell
gh release create v1.0.0 ./my-wallpaper.spatial --repo AUTHOR/WALLPAPER --title "My wallpaper 1.0.0"
~~~

不要标为 draft 或 prerelease。Release 标签、资产名、数字 Release/asset ID、实际大小与 SHA256 一起绑定修订。删除后重传的资产具有新身份，需要新修订和重新审核。

## 提交初次登记或修订 PR

向公开市场的活动 dev 分支提交 PR。一个 PR 只新增一份元数据文件，不能混入脚本、源码、工作流、二进制或缓存。使用[投稿模板](../../.github/PULL_REQUEST_TEMPLATE/market.md)。在市场仓库中查看活动 dev 分支；不要向产品 main 提交发布合并。

初次登记可新增 market/registry/123456789.json：

~~~json
{"schemaVersion":1,"repositoryId":123456789,"repository":"AUTHOR/WALLPAPER"}
~~~

新作品或后续修订也可新增 market/submissions/123456789/11111111-2222-4333-8444-555555555555/1.0.1.json：

~~~json
{
  "schemaVersion": 1,
  "repositoryId": 123456789,
  "repository": "AUTHOR/WALLPAPER",
  "workId": "11111111-2222-4333-8444-555555555555",
  "revision": "1.0.1"
}
~~~

文件路径必须与内容完全相符。先在作者默认分支更新 wallpaper.json，并发布 v1.0.1 的完整包，再提交修订请求。维护者从 GitHub API 读取精确 PR head 的 JSON、作者默认分支清单和 Release；不会检出并运行投稿者仓库。个人仓库自动核对 PR 作者和数字所有者。组织或协作者投稿需要维护者另行核对目标默认分支控制证明，不需要提交高权限 PAT。

自动检查核对结构、版本、摘要、预算、许可和真实原生准入；维护者还审核分发权、操作说明、预览与行为。只有审核合并后，受保护发布环境重新下载并验证通过的包才进入签名 published 索引。绿色 PR 检查不是市场已经上线的证明。

## 参与评论、更新和撤回

每件作品使用公开市场中一条稳定 GitHub Issue，维护者以完整标记 spatial-market:数字仓库ID:作品GUID 建立关联。修订继续原串。客户端详情中的评论入口打开该 Issue：匿名访客可浏览，回复和反应使用 GitHub 浏览器登录；播放器不索要 PAT。隐藏、删除或锁定内容由 GitHub 和市场维护者处理，网络失败显示错误或由浏览器重试，不伪造评论。产品故障和举报使用[公开仓库 Issues](https://github.com/KyaKayKya/Spatial-Wallpaper-Community/issues)。

下载/安装更新后，正在播放的确切旧修订继续运行，直到你显式应用。删除 Release、撤回或下架不会自动删除本地作品、切换作品或改变音量。申请撤回时，在原作品 Issue 中说明作品 GUID 和修订，维护者审核后更新撤销清单；仍需另行处理有违法或侵权风险的公开资源。

热门榜使用 GitHub Release 资产下载计数的七日增量，包含重复下载、更新和机器人，不代表评分或安装人数。缺少完整窗口、限流或计数异常时显示未知；不把累计 lifetime 数值当成七日热度。实际部署状态和运行记录见[市场维护指南](壁纸市场维护.md)。

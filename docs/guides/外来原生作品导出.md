# 外来原生作品导出（SDK 0.4.0-preview.1）

便携发行包在 Authoring 的相邻目录附带 Python：从 Authoring 运行时，可将下文 `python` 替换为 `..\Python\python.exe`；NativeValidator 位于 `NativeValidator\NativeValidator.exe`。源码创作环境需要 Python 3.10+；Unity Editor 仅为创作依赖，播放无需安装。

面向使用 Unity 2022.3.62f3、URP 14.0.12 的作者。本格式支持规范静态场景数据和隔离作者脚本；支持范围小于产品内置原场景库。Showcase、Parking、Train、RainyCafe、MiniShot 使用原平台资产库，保留其原模型、烘焙、材质和可信行为，不经过本节的静态导出转换。

## 导出作品

1. 在独立的 GameObject 上添加 SceneDefinition，将 contentRoot 指向作品根节点。设置稳定的小写 GUID templateId、displayName、authorFrame 和许可来源；修订使用新的版本标签，保留 GUID。
2. 将作者逻辑写入带 WallpaperScript 标记的组件。每节点最多一个启用的作者组件。编译器仅接受既有隔离 C# 子集；任意 Unity API、任意 DLL 和 Editor 代码不会进入原生渲染宿主。
3. 在 Editor 代码中调用 SpatialWallpaper.Sdk.Editor.ExternalNativeExporter.Export(definition, 全新输出路径, "1.0.0")。输出后缀为 .spatial。该入口拒绝覆盖已有文件。
4. 使用随 SDK 分发的 NativeValidator.exe --package 作品.spatial --platform-index 任意占位路径 验证外来包。外来包不引用平台库，参数为与平台包 CLI 保持兼容而保留；不会读取占位文件。
5. 本导出入口输出 local-validation，不能直接投稿。按下节生成逐项许可声明，再用 prepare_shared_external.py 生成新的可审核包。确认分发权由作者作出；工具和验证器不能证明版权或代替市场审核。

作者脚本的 primitive、Vector3、Color、节点、Light、同作品脚本和递归数据字段可导出；数组、列表和节点图仍受 SDK 准入上限约束。脚本可修改 Transform/Light，并使用已实现的 View、异步查询、Storage 等能力。当前外来脚本的 Material、Mesh、Texture、AudioClip 和 Prefab 字段引用尚未映射，非空引用会明确拒绝。原平台五包已有独立资源目录和声音绑定，不受此限制。

## 准备分发权声明和投稿包

准备 Python 3.10+ 和匹配发行中的可信 NativeValidator.exe；完整保留验证器同目录的配置和 Newtonsoft.Json.dll。源码快照中脚本位于 tools/wallpapers/，发行目录中对应 Authoring/tools/wallpapers/。以下命令从源码快照根目录运行；使用发行工具时替换脚本路径。创作还需要上文的 Unity Editor/URP 和 SDK；普通用户安装、导入和播放不需要另装 Python 或 Unity。

先对本地导出做真实准入，并列出需要许可覆盖的准确资源路径和 SHA256：

~~~powershell
python -B ./tools/wallpapers/prepare_shared_external.py --package D:/MyWork/local.spatial --validator D:/SpatialWallpaper/Authoring/NativeValidator/NativeValidator.exe --list-resources > D:/MyWork/resource-inventory.json
~~~

检查退出码为 0。resources 包含 script.json，以及 assets/ 前缀下的场景、网格、纹理和 Shader Bundle；不包含两个仅用于身份/许可绑定的 manifest.json。每个 payload 至少归入一条真实权利记录。一个 Bundle 或场景文件包含多项来源时可以在多条记录中重复列出该资源，并在 source/attribution 中说明具体部分；不能因文件合并就省略第三方来源。

新建 license-records.json，使用如下结构。下面是填写格式，source、license、attribution 和 resources 必须替换为自己的实际来源、许可、署名及上一步返回的完整路径；不能直接把模板当成授权证明：

~~~json
{
  "schemaVersion": 1,
  "records": [{
    "name": "My original scene and script",
    "source": "https://github.com/AUTHOR/WORK/blob/FULL_COMMIT/LICENSE",
    "license": "LicenseRef-MyExplicitRedistributionGrant",
    "redistribution": "verified",
    "attribution": "实际作者、许可要求的署名以及授权覆盖范围",
    "resources": ["script.json", "assets/scene.json"]
  }]
}
~~~

还需添加记录以覆盖 resource-inventory.json 中的全部资源，包含实际 meshes/<SHA>.smesh、textures/<SHA>.stex 和 custom.shaderbundle 等路径。记录只接受上述六个字段；每个文本最多 8192 字符。resources 不接受未知路径或同一记录内重复路径，records 最多 4096 条、声明文件最多 1 MiB。verified 表示你已核实该记录的分发授权；不是程序自动得出的结论。付费素材、来源不明素材或许可禁止再分发时不要确认，也不要把它们改称原创。

明确确认拥有全部列出内容的分发权后执行：

~~~powershell
python -B ./tools/wallpapers/prepare_shared_external.py --package D:/MyWork/local.spatial --license-records D:/MyWork/license-records.json --confirm-rights --validator D:/SpatialWallpaper/Authoring/NativeValidator/NativeValidator.exe --output D:/MyWork/shared-1.0.0.spatial > D:/MyWork/shared-receipt.json
~~~

工具只接受 spatial-external-native-wallpaper/schema5；原平台五包始终拒绝。它在隔离临时目录对原包快照和新包分别调用真实 NativeValidator，不运行作者脚本。只有后置校验报告 license_share:true 且每条记录匹配后，才独占创建全新的输出文件；已有输出拒绝覆盖，原 local.spatial 不变。资源准入和脚本隔离继续由同一个验证器及运行时执行，不能把许可声明视为对脚本行为、驱动或 GPU 风险的认证。

检查退出码为 0、shared-receipt.json 的 before.valid/after.valid 为 true、after.license_share 为 true。unchanged_payload_sha256 应与原清单完全相同；脚本和全部视觉资源逐字节保留，只重建内层许可、reshare、build_id，以及外层许可和相应身份/摘要绑定。work_id 和 revision 保留。转换后的字节属于新构建：若该 revision 已经发布，回到 Unity 以新 revision 导出，不能用同一修订替换已有 Release 附件。

ZIP 不解压到用户目录；工具拒绝路径穿越、重复或大小写别名、链接/目录、加密条目和超预算资源。压缩包上限为当前市场的 64 MiB，展开总量及单资源另遵守既有原生准入预算。它不减少纹理分辨率或删减资产来满足预算。

按[市场创作者入门](壁纸市场创作者入门.md)把新的 .spatial 文件发布到作者公开 GitHub Release，并提交注册/修订元数据 PR。wallpaper.json 使用验证器实际输出的稳定 GUID、修订、SDK 和完整 capabilities；保留 license-records.json、授权材料和转换回执供维护者审核。工具不替你上传、投稿或取得第三方许可，绿色准入检查也不等于市场已收录。

## 当前接受和拒绝的场景

规范数据保留位置、旋转、缩放、层、三角网格子网格和完整的 position/normal/tangent/UV0/UV1/color、材质属性/关键字/渲染队列、完整分辨率纹理/支持的 mip、光照贴图及受控 Light。必要 Shader 通过专用 shader-only Bundle 传递；准入器在 Unity 加载 Bundle 前检查其原生对象类型和预算。

导出前明确拒绝以下内容，不将它们静默转换为近似效果：SkinnedMeshRenderer、Animator、blendshape、bindpose、UV2–UV7、非二维 UV0/UV1、缺失上述完整网格通道、非三角拓扑、不活跃节点、非默认阴影/排序配置、使用 Probe 的 Renderer、天空盒、非 Flat 环境光、雾、RGBAFloat/非 Texture2D 纹理，以及无法表达的纹理变换和其他作者组件。请保留源项目；收到拒绝时选择受支持的原创场景或等待对应格式能力完成，不删减原作品后声称等价迁移。

## 包格式和运行时

顶层 ZIP 恰有 manifest.json、script.json、assets.spatial。manifest.format 为 spatial-external-native-wallpaper；schema=5、SDK=0.4.0-preview.1、scene-command ABI=1，并绑定当前命令目录摘要、稳定 work_id、revision、内部资产 build_id 和每一字节的 size/SHA-256。

assets.spatial 是既有 canonical-static-data-v1 规范数据容器（内部数据序列化 schema2），不是旧 schema4 脚本包。script.json 是独立 schema5 原生脚本定义。准入分别校验外层身份、资产图/资源/许可、Shader-only Bundle 和作者程序，校验节点数及父子索引一致性；只有通过后才创建已知 Unity 类型。不会先加载陌生 Scene/Prefab 再扫描。

NativeExternalPackage.Validate 返回不可变 Manifest、ScriptDefinition、ValidatedPackage Data 和 EstimatedCost。ExternalNativeScene 在 OwnedDomain 预算内创建视觉实例；作者程序另在 ScriptWorker 执行。CloseAsync 后持续 PumpRetirement，只有 CanDisposeOwner 为 true 才释放 owner。GPU 完成依靠真实 fence，D3D11 回退使用独立四字节同步 token 的异步 GPU buffer 读回，不读取场景像素、不按固定帧数猜测完成。

## 原创可投稿示例

OriginalNativeExample.Run 生成自创三角网格和 CC0Example Shader，并带有真实 Transform 动画以及 View.GetEye/GetSize 读取。仅本示例新写内容按 CC0-1.0 提供；不会将原作品或 Unity 运行库改为 CC0。

使用 tools/sdk/export_original_native_example.py --unity Unity.exe --project 项目/Prototype --output 全新目录 --validator NativeValidator.exe 运行实际 Unity 导出和纯校验，receipt.json 记录来源提交、源文件摘要、退出状态、包摘要和许可检查。Python 和 Unity Editor 仅为创作工具依赖；普通用户运行导入后的壁纸不需要它们。

实际视觉、用户声音体验、物理多屏和长期运行由发行手动验收清单覆盖。编译和纯数据准入通过不能替代这些体验验证。

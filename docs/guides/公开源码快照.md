# 导出公共源码快照

本指南供发布维护者使用。你可以从一个冻结的完整提交 SHA 导出可审查源码，再将审查后的文件提交到 [Spatial Wallpaper Community](https://github.com/KyaKayKya/Spatial-Wallpaper-Community)。开发仓库继续用于开发；公共仓库承载公开源码、社区登记和发行资产。

导出工具只读取 Git 对象，不复制工作目录、不读取未提交文件、不携带私有 Git 历史，也不执行导出的代码。它不创建 GitHub 提交、PR 或 Release，不会修改分支保护、安装依赖或下载 LFS 对象。

## 准备冻结提交

你需要 Git 和 Python 3.10 或更新版本。普通用户运行 Windows 发行包不需要这些开发工具。

1. 在集成任务中提交并核实需要公开的实现，记录完整 40 位提交 SHA。不要使用浮动分支名或 `HEAD` 作为导出参数。
2. 确认公开范围。工具采用源码允许清单；你仍需审查导出结果的来源、敏感信息与许可，自动筛查不能证明文件拥有再分发权。
3. 选择不存在的输出目录。导出失败留下的部分目录也不会被下一次运行覆盖；核实其内容后另选一个新目录。

未提交的修复和本地独有素材不会进入快照。原工作目录、`Validation/Content/long-store`、正在使用的构建及其他任务文件都不参与导出。

## 生成快照

在仓库根目录运行：

```powershell
python tools/market/prepare_public_source.py `
  --repo . `
  --commit FROZEN_COMMIT_SHA `
  --output "C:\Project\GameAI\PublicSource\SNAPSHOT_NAME"
```

将 `FROZEN_COMMIT_SHA` 替换为已核实的完整提交 SHA，将 `SNAPSHOT_NAME` 替换为本次独立目录名。工具从该 SHA 的 `git ls-tree` 清单读取 blob；即使导出命令来自另一个工作目录，也不会混入该目录的脏文件。

成功后，终端输出冻结提交、源码文件数、字节数、保留许可数、排除原因计数以及 `SHA256SUMS` 的摘要。`publication` 为 `not-published`，表示只生成了本地快照。

工具保留以下内容：

| 内容 | 导出边界 |
| --- | --- |
| SDK、Authoring 与样例 | 保留 `Packages/com.spatialwallpaper.sdk` 中的文本源码、工具、文档和可保留的元数据；不附带样例二进制资产 |
| 原项目源码 | 保留明确项目模块中的脚本、Shader、编辑器与 UI 源码，以及项目设置和包依赖声明 |
| Supervisor、工具、测试与 Tracker | 保留文本源码、测试数据、依赖锁定文件；不附带执行文件、模型或缓存 |
| 市场元数据与自动化 | 保留 `market/*.json`、schemas、templates、requirements 及 `.github/workflows/market*`；工具只导出工作流，不执行或部署 |
| 第三方源码 | 保留有随附许可证的 Cilbox、fNbt 源码及其来源文件；不因发现第三方目录就自动授权其全部内容 |
| 许可说明 | 保留源码树内可识别的现有许可与署名说明；生成对应索引 |
| 公共操作文档 | 保留 SDK 文档与工具中列明的公共指南，不复制开发计划、审查证据或内部讨论目录 |

原作品 Scene、Prefab、材质、模型、贴图、烘焙、音乐、音效、第三方资产包和原资源清单不随源码快照分发。二进制、LFS 指针、符号链接、子模块、凭据文件、疑似令牌内容、构建输出、缓存及私有文档也会排除。Unity `.meta` 只随保留的文件或目录导出，避免孤立元数据。

发行版的 `MarketTrust.json` 公钥配置属于可公开的信任根，会随源码保留。私有签名密钥和服务凭据不能进入该配置或快照。工具与示例生成的原创资源可以从源码重新生成；未验证再分发许可的原五作品包不能仅因导出成功就进入公开市场。

单个文本文件上限为 2 MiB，总文本输入预算为 64 MiB。超限、非 UTF-8 或二进制输入会记录排除原因；整个快照超预算则导出失败。需要改变范围时修改并审查工具的允许清单，不要从原工作目录批量补拷文件。

## 核对输出

快照根目录包含以下生成文件：

| 文件 | 用途 |
| --- | --- |
| `README.md` | 说明源码用途、开发依赖和缺失素材；替代包含本机运行状态的开发仓库入口 |
| `SOURCE_MANIFEST.json` | 记录冻结 SHA、导出规则标识及每个源码文件的原 Git blob、原始字节数、SHA-256 和文件模式 |
| `SHA256SUMS` | 覆盖全部源码与生成说明文件；不递归包含自身摘要 |
| `OMITTED_INPUTS.json` | 列出省略的项目资产和依赖路径，供创作者恢复所需输入；不列出私有文档、凭据文件名或缓存内容 |
| `THIRD_PARTY_NOTICES.md` | 链接本次保留的现有许可证与署名说明 |
| `SOURCE_LICENSE_STATUS.md` | 反映冻结树中已存在的项目许可；本轮自有代码为 MIT，第三方和资产范围以 PROJECT_LICENSE_SCOPE.md 为准 |

你可以用 Python 标准库核对快照摘要：

```powershell
python -c "import hashlib,pathlib; p=pathlib.Path(r'C:\Project\GameAI\PublicSource\SNAPSHOT_NAME'); rows=[line.split('  ',1) for line in (p/'SHA256SUMS').read_text(encoding='utf-8').splitlines()]; assert all(hashlib.sha256((p/name).read_bytes()).hexdigest()==digest for digest,name in rows); print('Snapshot hashes verified:',len(rows))"
```

确认以下结果后再公开：

1. `SOURCE_MANIFEST.json` 的 `source_commit` 与本次冻结 SHA 一致，`history_included` 为 `false`。
2. 摘要核对通过。输出没有 `.git`、私有提交日志、私有文档、LFS 指针、发行缓存或执行文件。
3. 检查 `excluded_counts` 中的凭据与文本预算项。疑似凭据筛查只提供有限的静态识别；不要将它写成“已证明没有秘密”。
4. 检查 `OMITTED_INPUTS.json` 与许可索引，确认未补入未获授权的原作品或第三方资产。
5. 核对冻结树中的 LICENSE 与 PROJECT_LICENSE_SCOPE.md。本轮项目自有代码采用 MIT；原有第三方、素材和 CC0 示例许可不被重写。工具只反映已有选择，不自行授予素材再分发权。

## 恢复开发输入

SDK 创作者可以从 [SDK 入门](../../Packages/com.spatialwallpaper.sdk/Documentation~/GettingStarted.md) 开始，使用自己的获授权素材。完整 Unity 产品工程需要按照 `OMITTED_INPUTS.json` 恢复对应资产和独立依赖。快照不会把缺失资源降质替换成其他模型或静态图片。

源码中的部分文档链接指向开发仓库内未公开的证据；这些链接不表示证据已随快照公开。开发脚本也可能引用原本的本地验证目录。你需要单独准备 Unity 2022.3.62f3、相应平台工具链与获授权资产，才能构建完整原作品库。源码快照的生成与摘要验证不等于全工程已在干净机器上构建通过。

普通用户使用单独交付的完整便携发行目录。公开 Releases 仅发布已经核实分发许可的 SDK、验证器与原创示例；五原作品完整本机发行包尚未作为公开下载上传，不能把源码快照或验证器 ZIP 当作完整安装包。运行发行包不应依赖这个源码快照、开发工作目录、Python 或 Unity Editor。

## 提交到公共仓库

在公共仓库的独立干净 clone 中创建发布分支，审查快照与已有社区文件的组合差异，再精确暂存需要发布的文件并创建 PR。沿用公共仓库实际的审查与合并规则。

不要把开发仓库的 `.git`、对象目录、私有分支或历史推送到公共仓库。不要使用镜像推送、强推或目录镜像删除来覆盖公共仓库已经存在的市场登记、工作流或讨论关联。工具不会替你执行这些操作，也不会把本地快照标记为已上线。

提交完成后核对公共 PR 的实际文件、来源 SHA、许可状态与摘要，再按版本流程发布对应发行资产。正式发行必须从同一已冻结、已审查提交构建；只生成本地源码快照不满足安装包交付标准。

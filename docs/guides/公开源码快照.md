# 从开发版本同步到公开仓库

本指南供发布维护者使用。私有开发仓库维护代码、文档和工具；[公开仓库](https://github.com/KyaKayKya/Spatial-Wallpaper-Community)承载可公开源码、社区投稿和发行资产。普通使用者从[项目首页](../../README.md)开始，无需执行本页。

## 固定流程

~~~text
私有任务分支 → 相关验证 → PR / merge commit → 唯一活动 dev
                                                    ↓ 冻结完整 SHA
                                  同步 dry run → 本地公开任务提交
                                                    ↓
                                     公开 PR → merge commit
                                                    ↓
                          用户验收版本 → 版本 PR → main / 唯一标签
~~~

源码同步不会重新构建播放器，也不会替代产品验收。只改文档时验证链接、图片和快照摘要；代码改动做相关编译与最小检查。完整安装包仍从同一冻结源码构建，单独核对依赖与分发许可。

## 准备一次，后续复用

准备 Git、Python 3.10+，确认当前认证账户有权推送公开仓库。开发依赖与播放器运行依赖分开。

在**项目内部**准备独立公开 clone；不要把私有 .git、分支或对象库复制过去：

~~~powershell
git clone https://github.com/KyaKayKya/Spatial-Wallpaper-Community.git .local/public-repo
~~~

这份 clone 只供公开同步使用，保持干净。工作区、快照和诊断都留在项目内部 .local 或 Validation，不在 GameAI 顶层创建 PublicSource、Deliveries 或临时测试项目。不要对正在运行的主目录构建执行目录镜像。

## 先在开发分支完成改动

1. 从私有仓库唯一活动 dev 分支建立任务分支与隔离 worktree。
2. 修改源码及其文档。公开首页维护源为 docs/public/README.md，英文首页为 docs/public/README.en.md，仓库简介/主题配置维护在 docs/public/repository.json；图像放 docs/public/assets，并记录来源。入口链接以**公开根目录**为基准编写。
3. 完成相关检查，经 PR 以 merge commit 合入活动 dev。
4. fetch 后记录该 dev 的完整40位SHA。本轮发布只使用这个冻结值；未提交文件不会导出。

公开贡献若修改了已同步源码，先审核并带回私有开发源，再冻结回传。同步器遇到公共侧独有修改会拒绝覆盖；不要删除保护或用强推消除冲突。

## 审查同步计划

在开发仓库根目录运行。将 FROZEN_COMMIT_SHA 替换为完整SHA，PUBLIC_DEV_BRANCH 替换为公开仓库实际 dev 分支，SHORT_SHA 替换为本轮短标识：

~~~powershell
python -B tools/market/sync_public_source.py --repo . --commit FROZEN_COMMIT_SHA --public-repo .local/public-repo --base PUBLIC_DEV_BRANCH --branch task/public-source-SHORT_SHA
~~~

默认是 dry run：它 fetch 公开基线、从 Git 对象导出并核对快照摘要，列出 changed / removed；不会切换公开工作区、提交、推送或创建 PR。确认以下内容：

- 来源SHA正确，公开clone远端确实是指定社区仓库，base为活动dev分支。
- changed包含预期源码和图文模板；removed只涉及上次清单拥有且本次退出范围的源码。
- 没有原素材二进制、私有历史、凭据、本地缓存或用户存档。
- 所有首页图像和指南链接都在快照中存在；不能用开发仓库里未公开的文件充当公开导航。

发现脏文件、未知覆盖、公共侧已改文件、路径或摘要不一致时，命令失败并报告原因。先解决真实差异，不用全仓暂存、目录镜像删除或重建缓存绕过。

## 生成可审查提交，再创建 PR

确认计划后，在同一命令末尾加 --apply：

~~~powershell
python -B tools/market/sync_public_source.py --repo . --commit FROZEN_COMMIT_SHA --public-repo .local/public-repo --base PUBLIC_DEV_BRANCH --branch task/public-source-SHORT_SHA --apply
~~~

它只在公开clone的新任务分支创建本地提交，不自动推送或合并。文件以原Git blob字节入index，避免Windows CRLF和过滤器改写摘要；切分支禁止覆盖被忽略的本地文件。命令完成后检查公开 diff 与 SOURCE_MANIFEST.json，再按输出的 next_commands_argv 推送任务分支，使用GitHub创建目标为公开dev的PR。

PR写清私有冻结来源SHA、修改目的、导出/链接/图片检查、许可边界及未运行项。审查后使用 **Create a merge commit**。随后 fetch并核对实际合并SHA。仓库简介或主题改变时，从已验证的 repository.json 通过 GitHub 仓库设置/API 应用，并读回核对；这些设置不属于Git文件，源码提交不会自动改变它们。

同一已合并来源SHA再次同步应报告无变更，不创建重复提交。新的源码变更使用新的冻结SHA和新的任务分支；已经合并的任务分支不追加提交。

## 同步范围与公开运营数据

| 内容 | 谁维护 |
| --- | --- |
| SDK、Supervisor、项目脚本、工具、测试、Tracker文本源码 | 私有开发源，按允许清单同步 |
| 根README、英文首页、公共指南与显式文档图片 | 私有docs/public与公共指南，审核后同步 |
| .github/workflows/market*、schema和投稿模板 | 私有开发源，按工作流权限与可信代码边界审查 |
| registry、submissions、details、previews、wallpaper.json、featured和revocations | 公开运营数据，独立PR维护；源码同步不覆盖或删除 |
| 原Scene/Prefab、模型、贴图、音乐、第三方资产及大缓存 | 不随源码公开；单独取得许可后才能发行 |
| 签名私钥、令牌、DPAPI本机材料和用户存档 | 永不进入源码快照或公开仓库 |

静态SVG仍接受凭据筛查与被动内容检查；位图只允许明确文档目录、支持格式和有限预算。静态筛查不能证明不存在秘密或拥有素材版权，维护者仍需审查实际差异。

## 核对公开产物

公开快照包含 SOURCE_MANIFEST.json、SHA256SUMS、OMITTED_INPUTS.json、SOURCE_LICENSE_STATUS.md 和 THIRD_PARTY_NOTICES.md。manifest记录source_commit、每文件SHA256与原Git blob；首页由维护模板生成，不再被技术性快照说明替换。

需要单独导出而不创建公开提交时：

~~~powershell
python -B tools/market/prepare_public_source.py --repo . --commit FROZEN_COMMIT_SHA --output .local/public-snapshots/SHORT_SHA
~~~

输出目录必须不存在。工具只读冻结Git对象，不执行冻结源码、不读取未提交修改、不下载LFS或部署服务。源码快照不是完整Unity原作品项目；恢复构建输入前先核对OMITTED_INPUTS及许可。

## 维护首版与后续版本

main通过版本PR保存用户明确验收的基线，使用merge commit和唯一版本标签，不移动旧标签。预览基线如实保留预览成熟度与未完成验收。活动dev只能有一个；版本收尾后先处理未合并任务、保存独有资料、清理闲置worktree，再按下一版本安排建立新的dev分支。

市场包审核、签名索引和桌面完整发行各自有验证与许可要求。公开源码成功不代表完整安装包已经上传，也不代表摄像头、音效、多屏或长期体验已经通过。
